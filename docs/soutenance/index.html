SEC-03 — Prise de contrôle de compte

Le défaut n'était pas un mauvais code.
C'était une absence.

Avant — n'importe qui, n'importe quel compte

app.post('/auth/reset-password', async (req, res) => {
  const { email } = req.body
  // aucun jeton, aucune vérification de propriété
  const newPassword = Math.random().toString(36).slice(-8)
  const hash = await bcrypt.hash(newPassword, 10)

  await pool.query('UPDATE users SET password_hash = $1
                    WHERE email = $2', [hash, email])

  console.log(`[RESET] New password for ${email}:
               ${newPassword}`)
  res.json({ message: 'Password reset email sent' })
})

Après — preuve de possession obligatoire

const token = crypto.randomBytes(32).toString('hex')
await pool.query(`INSERT INTO password_resets
  (token_hash, user_id, expires_at) VALUES ($1, $2,
   NOW() + INTERVAL '30 minutes')`,
  [hashToken(token), user.id])
await mailer.sendPasswordReset({ email, token })

// Réponse identique si le compte n'existe pas

Jeton

Aléatoire, stocké haché, usage unique, trente minutes.

Journal

Le mot de passe finissait dans /logs/, exposé publiquement par Nginx.

Énumération

QUA-05 — La fraude aux congés

Une ligne.
Trois défauts.

const nombreJours = Math.ceil(
  (new Date(dateFin) - new Date(dateDebut)) / (1000 * 60 * 60 * 24)
)
01

Valeur négative

Des dates inversées produisent un nombre négatif, qui vient augmenter le solde. Un formulaire suffit.

02

Jours non ouvrés

Week-ends et jours fériés décomptés comme des jours travaillés.

03

Borne exclue

Un congé d'une seule journée valait zéro jour.

Corrigé à trois niveaux, parce qu'un seul ne suffit pas.

Domaine

Jours ouvrés, bornes incluses, fériés mobiles calculés — Pâques, Ascension, Pentecôte.

Application

Chevauchement et solde disponible vérifiés sous verrou, dans une transaction.

Base

CHECK (date_fin >= date_debut) — une contrainte ne se commente pas « temporairement ».

Plan de remédiation

Trois règles ont dicté l'ordre

01

On referme d'abord ce qui est ouvert

Un pipeline exemplaire qui déploie un système ouvert reste un système ouvert. La rotation des secrets passe donc avant l'injection SQL : la clé Stripe sk_live_ et les clés AWS sont exploitables sans passer par l'application.

02

On ne teste pas du code qu'on va réécrire

Écrire les tests avant les correctifs aurait figé le comportement défectueux dans la suite de tests.

03

On n'automatise pas un déploiement sans retour arrière

Leçon directe du P1 : la panne n'a pas duré 3 h 07 à cause de la migration, mais parce que personne ne savait l'annuler.

Périmètre

Ce que nous n'avons pas fait —
et pourquoi c'est un choix.

i

Corriger le barème de cotisations

Les taux sont annotés « approximatif » dans le code d'origine. Un défaut d'arrondi est technique — nous l'avons corrigé. Un taux réglementaire ne l'est pas : le modifier sans validation d'un expert-comptable remplacerait une erreur par une autre, avec la même apparence de justesse.

ii

Émettre les bulletins à temps partiel

Le barème ne les couvre pas. Nous refusons l'émission plutôt que de calculer faux : un bulletin non émis est un incident visible, un bulletin faux est un contentieux différé.

iii

Migrer vers Kubernetes

Cinq services, 8 200 utilisateurs, une équipe qui vient de perdre son unique expert. On adopte le modèle correspondant à la maturité réelle, pas au modèle idéal.

iv

Trancher le sort des bulletins déjà émis

Décision juridique et comptable. Nous la signalons ; elle ne nous appartient pas.

Le post-mortem du 14 août listait cinq actions décidées. Dix jours plus tard, son auteur écrivait : « Status : aucune action réalisée à ce jour ». Aucune n'avait de responsable ni d'échéance. C'est pourquoi chaque ligne de notre suivi renvoie à une preuve exécutable

Anti-sèche

Ce qu'on nous demandera

Q1

Pourquoi supprimer /paie/migrate au lieu de la sécuriser ?

Une migration de schéma n'est pas une fonctionnalité. Elle ne doit pas s'exécuter dans le processus qui sert le trafic, quel que soit le contrôle d'accès. ADR-001

Q2

Pourquoi cinq étapes et pas trois ?

Chaque étape répond à un incident distinct. Fusionner deux étapes, c'est perdre la traçabilité de ce qu'on empêche.

Q3

Le retour arrière annule-t-il les migrations ?

Non — il ramène le code, pas les données. Les migrations sont donc écrites compatibles avec la version précédente. La restauration de données est une procédure distincte, à décision explicite.

Q4

Pourquoi pas de cookie httpOnly tout de suite ?

Il exige la protection CSRF et le partage de domaine. Travail justifié, mais qui ne doit pas retarder la fermeture d'une exposition au vol de jeton. ADR-003

Q5

Comment prouvez-vous le délai de détection ?

Par une panne provoquée en recette : on coupe un service, on chronomètre l'alerte, on consigne. Une supervision jamais déclenchée est une hypothèse.

Q6

Qu'est-ce qui vous a le plus surpris ?

Que le pipeline existant ne pouvait pas réussir : le frontend n'était pas constructible. Personne ne l'avait remarqué, parce que personne ne regardait les exécutions.
