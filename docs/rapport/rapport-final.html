Synthèse

L'audit technique commandé par Partech décrivait une dette accumulée depuis 2021. Notre propre audit, conduit sans reprendre la liste existante, aboutit à un constat plus direct : HRFlow n'était pas un système fragile, c'était un système ouvert.

À la date de la reprise, un attaquant sans compte, sans outil et sans connaissance préalable pouvait, en moins de dix minutes, lire l'intégralité des données RH de tous les clients, prendre le contrôle de n'importe quel compte, provoquer une coupure totale de la plateforme et forger des jetons d'authentification valides. Ces quatre expositions ne relevaient pas de la dette technique : c'étaient des vulnérabilités actives.

Ce rapport documente 51 constats, dont 12 que l'audit externe n'avait pas relevés. Trois d'entre eux invalident des correctifs que l'on serait tenté d'appliquer en confiance : réactiver les tests, s'appuyer sur le build existant, déployer d'abord en environnement de recette.

1 · L'audit : méthode et résultats

1.1 Une relecture menée à froid

L'audit a été conduit en quatre passes volontairement séparées. La deuxième est la seule qui compte vraiment : 100 % des fichiers relus ligne à ligne, sans la liste Partech sous les yeux. C'est elle qui a produit les douze constats supplémentaires. Se contenter de confirmer une liste existante aurait donné un rapport plus rapide et strictement inutile.

Les commentaires laissés dans le code — // TODO, // à retirer, // jamais fait — ont été traités comme des indices, jamais comme des preuves. Les problèmes les plus graves ne portaient aucun commentaire : personne, dans l'équipe précédente, n'en avait conscience.

1.4 Deux exemples représentatifs

La fraude aux congés — une ligne, trois défauts

const nombreJours = Math.ceil(
  (new Date(dateFin) - new Date(dateDebut)) / (1000 * 60 * 60 * 24)
)

Des dates inversées produisent une valeur négative, qui vient augmenter le solde du salarié. Les week-ends et jours fériés sont décomptés comme ouvrés. La borne finale est exclue, donc un congé d'une journée vaut zéro jour. Corrigé à trois niveaux : domaine, application, et contrainte de base — CHECK (date_fin >= date_debut), parce qu'une contrainte de base ne se commente pas « temporairement ».

La prise de contrôle de compte — le défaut était une absence

app.post('/auth/reset-password', async (req, res) => {
  const { email } = req.body
  // aucun jeton, aucune vérification de propriété
  const newPassword = Math.random().toString(36).slice(-8)
  await pool.query('UPDATE users SET password_hash = $1 WHERE email = $2', [hash, email])
  console.log(`[RESET] New password for ${email}: ${newPassword}`)
})

La route réinitialisait le mot de passe de n'importe quelle adresse fournie, sans preuve de possession, et l'écrivait en clair dans un journal que Nginx servait publiquement sur /logs/. Deux vulnérabilités qui se composent : la seconde transformait la première en compromission silencieuse.

2 · Les décisions structurantes

Huit décisions sont consignées dans docs/ADR.md avec leur contexte et leurs conséquences, y compris négatives. Les cinq qui engagent le plus :

ADR-001 — Supprimer les routes dangereuses plutôt que les sécuriser

L'audit externe recommandait de « sécuriser ou supprimer » la route de migration. Nous avons supprimé. Une migration de schéma n'est pas une fonctionnalité de l'application : elle ne doit pas s'exécuter dans le processus qui sert le trafic, quel que soit le contrôle d'accès exigé pour la déclencher. Une route de debug protégée reste une route de debug — sa protection est ce qu'on oublie de vérifier.

ADR-002 — Refuser de démarrer plutôt qu'appliquer une valeur par défaut

Le code contenait process.env.JWT_SECRET || 'novatech_jwt_super_secret_key_…'. Ces valeurs de repli permettent à un service de démarrer dans un environnement mal configuré. C'est précisément le problème : il démarre, il paraît fonctionner, et il signe des jetons avec un secret public. Un service dont la configuration est incomplète refuse désormais de démarrer.

ADR-004 — Aucune action tierce dans le pipeline

Le pipeline audité utilisait appleboy/ssh-action@master : une référence mutable, dont le code s'exécutait automatiquement avec les identifiants de production. Le fichier de workflow est plus verbeux aujourd'hui — le déploiement SSH est écrit à la main — mais il est auditable.

ADR-005 — Reprendre le barème de paie à l'identique

Les taux de cotisation étaient annotés « approximatif » et « à vérifier avec le comptable ». Nous avons corrigé ce qui relève de la technique — arrondis au centime en arithmétique entière, idempotence, transactions — et repris les taux sans y toucher. Corriger un taux réglementaire sans validation d'un expert-comptable remplacerait une erreur par une autre, avec la même apparence de justesse.

ADR-007 — Des drapeaux en configuration, pas un service externe

Le temps partiel n'est pas couvert par le barème : plutôt que d'émettre un bulletin faux, le service refuse. La fonctionnalité est déployée mais éteinte, et s'activera entreprise par entreprise une fois le barème validé. Un bulletin non émis est un incident visible ; un bulletin faux est un contentieux différé.

4.2 Causes racines — notre lecture

Le post-mortem d'origine identifie cinq causes techniques. Elles sont exactes, mais elles décrivent des symptômes. La cause commune est ailleurs.

Aucun de ces problèmes n'est apparu par surprise. Tous étaient connus, documentés dans le code par leurs propres auteurs, et repoussés. Le middleware d'authentification portait // TODO: remettre après fix depuis mars 2024. La route de debug portait // à retirer depuis juillet. Le .gitignore portait // TODO : à corriger — Théo 14/08/2024 (jamais fait).

La défaillance n'est pas technique, elle est processuelle : rien, dans la chaîne de livraison, n'empêchait de livrer du code défectueux.

4.3 Ce que le post-mortem d'origine ne dit pas

Il liste cinq actions décidées. Dix jours plus tard, son auteur écrivait : « Status : aucune action réalisée à ce jour. » Aucune de ces cinq actions ne portait de responsable ni d'échéance.

Une action corrective sans responsable ni date n'est pas une action corrective. C'est pourquoi chaque ligne de notre suivi de remédiation renvoie à une preuve exécutable — un test qui échoue si la vulnérabilité se rouvre, ou une vérification que le pipeline applique à chaque demande de fusion.

Sur l'historique Git

Les secrets d'origine étaient présents dans les premiers commits. Lors de la publication du dépôt, la protection de secrets de GitHub a refusé le push en détectant la clé Stripe — confirmation indépendante du constat SEC-01. L'historique a été purgé conformément à notre propre plan : le .env est retiré des 37 commits et les onze valeurs de secrets sont remplacées, sans effacer le code vulnérable d'origine, qui reste consultable.

Cela ne dispense pas de la révocation. Un secret publié est un secret compromis, même retiré : la purge traite la trace, pas l'exposition passée.

Executive summary — English

Context. NovaTech's HRFlow is a SaaS HR platform serving 8,200 users across 47 client companies, under a 99.5 % monthly availability commitment. A three-hour outage on 14 August 2024, followed by a technical audit commissioned by Partech Ventures, froze €1.8 M of a funding round pending a credible remediation plan.

What we found. Our own audit — deliberately conducted without the external report at hand — recorded 51 findings, 12 of which the external audit had missed. The system was not fragile; it was open. An unauthenticated attacker could read every client's HR data, take over any account, bring the platform down, and forge valid authentication tokens.

Three of the twelve additional findings invalidate remediations one would otherwise apply in good faith: the root npm test script returned success unconditionally, so re-enabling the test gate would have changed nothing; the frontend could not be built, so the pipeline's build stage was decorative; and the deployment script accepted an environment argument it never used, meaning deploy.sh staging deployed production.

How it was done

  • A five-stage pipeline — build, test, security, staging, production — where four stages block the merge. Each gate closes an incident that has already happened; none is theoretical.
  • 279 automated tests, a large share of which assert the absence of a vulnerability rather than the presence of a feature.
  • Immutable container images tagged by commit hash. The server no longer runs git pull and rebuilds: what is tested is exactly what runs.
  • Honest health probes. The previous endpoint returned 200 OK unconditionally — monitoring wired to it would have stayed green throughout the outage.
  • Scripted, tested rollback in roughly two minutes. The August outage lasted three hours not because of the migration, but because nobody knew how to undo it.

What we deliberately did not do

We did not correct the payroll contribution rates. They are wrong, and we say so — but changing a statutory rate without a chartered accountant's validation would replace one error with another, wearing the same appearance of correctness. Part-time payslips are therefore refused rather than computed: an unissued payslip is a visible incident, an incorrect one is a deferred dispute.

We did not migrate to Kubernetes. Five services, 8,200 users, and a team that has just lost its only expert: the added operational complexity would outweigh the benefit. We adopted the model matching actual maturity, not the ideal one.

Secret rotation remains outstanding. The procedure is written; execution requires production credentials a development team does not hold. Notably, GitHub's own push protection rejected our first push after detecting the Stripe key in history — an independent confirmation of finding SEC-01.

The core insight. None of these problems appeared by surprise. Every one was known, documented in the code by its own authors, and postponed. The failure was not technical but procedural: nothing in the delivery chain prevented defective code from shipping. The pipeline does not make the team more disciplined — it makes indiscipline visible immediately, rather than in an audit report six months later.
